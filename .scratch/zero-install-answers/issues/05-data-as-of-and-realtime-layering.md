# 05 — 落地頁標明資料截止日與即時性分層

**What to build:** 使用者知道自己看的是哪一天的班表，也知道「今天實際會不會誤點／停駛」要去哪裡查。靜態落地頁在即時性這條軸線上本質上贏不了每 10 秒更新的即時追蹤網站與有延誤推播的原生 App —— 本票不是去追平，而是把界線講清楚：**今天以前不會變的事，落地頁在 0.5 秒內全部給你；今天才知道的事，點一下進 SPA。**

明確標示資料截止日期反而把弱點轉成可信度：資料刷新週期為每兩天，這件事藏不住，但標了日期的頁面比沒標的更值得信，而且使用者知道要點進去看今天狀況。

**Blocked by:** 04 — 落地頁印出平日／假日班次表（「資料截至」這句話是在描述班次表，表尚不存在時這個標示是空的）

**Status:** ready-for-agent

- [ ] 每頁顯示資料截止日期，取自產生時所使用的資料集
- [ ] 明確指引使用者到 SPA 查詢今日誤點與停駛
- [ ] 措辭不承諾靜態頁具備即時性；與現有高鐵 FAQ 已有的誠實分層說法（明寫需點擊後才即時讀取）保持同樣的紀律
- [ ] 中英文兩種語言、台鐵與高鐵兩套模板都有
- [ ] SEO 驗證新增斷言：資料截止日期存在且為合法日期格式
- [ ] 落地頁仍不含任何外部 script 引用或 runtime fetch
