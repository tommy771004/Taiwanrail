# 04 — 落地頁印出平日／假日班次表

**What to build:** 使用者從 Google 搜「臺北到花蓮 火車時刻表」點進落地頁，**不下載任何 JavaScript** 就直接看到該 OD 的全部直達班次。目前頁面上除首末班外沒有任何時刻、也沒有任何車次號碼，要看到班次得等 SPA 載入約 455 kB JavaScript 再抓約 0.55 MB 班表 —— 使用者的實際行為是跳回 Google。這是本專案相對原生時刻表 App 唯一的結構優勢（零安裝、Google 找得到），本票是把它兌現。

**Blocked by:** 03 — 落地頁班次數改為 ServiceDay 正確（需要它 prefactor 出來的班次清單與平日／假日分組）

**Status:** ready-for-agent

- [ ] 每頁列出該 OD 的**全部**直達班次，不做取樣（取樣等於沒回答問題，使用者仍得跳 SPA）
- [ ] 每一列包含車次號碼、車種、出發時刻、抵達時刻、行駛時間
- [ ] 分平日與假日兩張表，各自可辨識
- [ ] 尾段時段以**瀏覽器原生的可折疊區塊**收起；切點依**時段**（例如中午之後）而非固定列數 —— 各 OD 班次密度差距達四倍（26 班至 101 班），固定列數在稀疏路線上會產生怪異切點
- [ ] 折疊區塊內的內容仍是可爬取的 HTML
- [ ] 台鐵與高鐵**兩套頁面模板** × 中英文，四種組合都有班次表
- [ ] 資料來源為 committed 的每週通用時刻表，**不使用 14 天每日快照**（刷新週期為每兩天，印出具名日期的班次會讓頁面長期掛著過期時刻）
- [ ] 落地頁維持零 JavaScript：不含外部 script 引用、不新增任何 runtime fetch
- [ ] SEO 驗證新增斷言：每列都有車次號碼與出發、抵達時刻
- [ ] SEO 驗證新增斷言：**各表列數與頁面文案聲明的該類別班次數一致**（此自我一致性斷言取代把 `ServiceDay` 分組計算複製到測試裡）
- [ ] SEO 驗證新增斷言：可折疊區塊存在、頁面無外部 script
- [ ] 頁面體積在合理範圍。可寫成上限**預算**（同 bundle 體積驗證既有的作法），但不得斷言確切位元組數。2026-07-30 觀測：現況約 12 KB；班次數最多的路線為 101 班，加表後預期不超過約 45 KB
- [ ] 折疊切點與班次密度的描述（當時觀測為 26 至 101 班）僅供判斷用，不得寫成常數
- [ ] 台鐵票價**仍未**出現在落地頁（維持既有限制，見 Out of Scope）
