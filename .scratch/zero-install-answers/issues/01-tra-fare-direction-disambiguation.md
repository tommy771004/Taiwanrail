# 01 — 台鐵票價方向消歧義：SPA 顯示實際路線票價

**What to build:** 使用者在 SPA 查詢台鐵班次時，票價徽章顯示的是實際直達路線的票價，而不是繞行環島另一側的票價。搜臺北→花蓮，自強系顯示 NT$583（目前顯示 NT$1676）。TRA ODFare 對每組 OD 同時提供順行與逆行兩筆，同車種只有行駛距離較短的那筆對應實際直達路線；消歧義規則收在一個共用的純契約模組裡，由票價 getter 在回傳前套用，因此上層與未來的消費端都不需要知道這件事存在。

> **不要把票價金額寫進程式或測試。** 本文件中出現的金額（583、1676 等）是 2026-07-30 當下資料的**觀測值，僅供人工核對方向是否正確**，不是規格。票價會隨資料刷新（每兩天）與台鐵調價變動，且 583 這個值尚未與台鐵官方管道核對過。斷言必須是**關係式**的 ——「回傳的是候選中行駛距離最小的那筆」在任何票價下都成立；「回傳 583」則會在合法調價後變成假警報，並把未驗證的數字固化成規格。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [x] 消歧義規則位於單一共用純模組，同一組（目的地站, 車種）只保留行駛距離最小的紀錄
- [x] 該模組不使用任何 Node 或 DOM global（與既有的 affiliate 純契約模組同一約束，因為瀏覽器與 build 期腳本都會 import）
- [x] 票價 getter 的**靜態檔路徑與 live TDX 降級路徑都**經過消歧義
- [x] **測試中不得出現任何寫死的票價金額或行駛距離常數**；期望值一律由 fixture 當場導出
- [x] 斷言：對任一具雙方向紀錄的 OD，每個車種只回傳一筆
- [x] 斷言：回傳的那一筆，其行駛距離等於該（目的地站, 車種）所有候選中的最小值
- [x] 斷言（迴歸方向）：回傳的**不是**行駛距離最大的那筆 —— 這是目前的錯誤行為，缺這條就抓不到退步
- [x] 斷言：單方向 OD 不受影響（抽樣中有 6 組）；同一 OD 的多個車種各自獨立消歧義；缺少行駛距離欄位時的行為明確
- [x] 測試以 committed 的真實票價資料檔為 fixture，而非手寫假資料（同時具備迴歸保護與「TDX 回傳結構改變時立刻失敗」的偵測能力）
- [x] 先確認新測試在修正前確實失敗，再修到綠
- [ ] 人工驗收（不寫成測試）：SPA 搜臺北→花蓮，自強系票價由改動前的觀測值 1676 降為 583；抽查一組相鄰站短程 OD，確認不再顯示環島一圈的價格（已知最壞案例誤差達 73 倍）
- [x] SPA 的班次卡票價對照邏輯未被修改（以車種為鍵的覆蓋在 getter 保證每車種一筆後即無害）
